## Overview

OnlyMap JS (`@nika-js/onlymap`) builds an interactive WebGL map from a small set of HTML custom elements. You write the layers, widgets, popups, interactions, and guided tours as markup. The library does the rendering, the data loading, the live updates, the picking, and the validation. You do not write deck.gl setup code, shader code, or a build step. One HTML file is a complete map application.

OnlyMap JS is also made for AI agents to write. HTML is a reliable output format for a model. The package includes an agent skill and an `llms.txt` file. `OmMap.validate()` returns structured errors, and each error has a fix. Together these give an agent a real authoring loop.

```html
<om-map center="[-122.42, 37.77]" zoom="11" basemap="positron">
  <om-layer id="quakes" type="ScatterplotLayer"
            data="./quakes.json"
            label="Earthquakes" color="#e63946"
            get-position="[$lon, $lat]"
            get-radius="scale($mag, sqrt, [2, 20], domain=[0, 8])"
            pickable></om-layer>
  <om-widget type="legend" position="top-right"></om-widget>
</om-map>
```

## Install

Install the package from npm:

```bash
npm install @nika-js/onlymap
```

Import the library and its stylesheet:

```js
import "@nika-js/onlymap";
import "@nika-js/onlymap/onlymapjs.css";
```

You can also load it from a CDN with no build step:

```html
<link rel="stylesheet" href="https://unpkg.com/@nika-js/onlymap/dist/onlymapjs.css">
<script type="module" src="https://unpkg.com/@nika-js/onlymap"></script>
```

Bundler support: Vite, webpack 5 (Next.js, Create React App), and Rollup all work — webpack required `@nika-js/onlymap@0.6.19` or later. Use a raw-file CDN (unpkg, jsDelivr) — the bare package URL serves a single-file standalone bundle built for this. Do not use a rebundling CDN such as esm.sh or skypack: re-bundling duplicates the deck.gl/luma.gl runtime and every layer fails shader compilation.

Building a mobile app? The same runtime ships as an Expo React Native
adapter, `@nika-js/onlymap-native` — see [React Native](/onlymap/react-native).

Two optional commands complete the setup:

- **`npx @nika-js/onlymap init`** — adds VS Code IntelliSense for every `om-*` element and attribute. It also adds `!`-prefix snippets (`!starter`, `!map`, …).
- **`npx -y skills add NikaGeospatial/onlymapjs --skill onlymapjs`** — installs the OnlyMap authoring skill into coding agents (Claude Code, Cursor, Codex). The agents then write correct manifests on the first try.

## Key Features

### Declarative Everything
- **41 layer types by name**: all of deck.gl's core, geo, aggregation, and mesh layers (Scatterplot, GeoJson, Arc, Path, Heatmap, Hexagon, Trips, Tile, Tile3D, Scenegraph, and more). It adds a built-in `PopupLayer` for WebGL labels at scale, a native `COGLayer` for GeoTIFF rasters, a `ZarrLayer` for chunked Zarr/GeoZarr rasters, an `ImageOverlay` for georeferenced drone photos, a `BIMLayer` for in-browser IFC models, `Route`/`Tracking` for styled routes and live position tracking, a `HillshadeLayer` for shaded relief, and a `TextOnPathLayer` for labels that follow a line.
- **Live manifest**: the markup is the state. When you change an attribute — from a widget, a behavior, a script, or devtools — the map updates automatically.
- **Satellite imagery without a key** <sup>new in 0.11.10</sup>: `basemap="satellite"` shows a cloud-free satellite view of the whole world (EOX Sentinel-2 cloudless), free for commercial use with its credit — detailed to about city-district zoom. Sharper, current imagery remains the keyed `maptiler-satellite`.
- **Built-in undo and redo**: you can undo a layer toggle, a filter change, a basemap switch, an element edit, or a drawn sketch. Use `<om-widget type="undo-redo">` or Cmd/Ctrl-Z.
- **Clustering as a toggle** <sup>new in 0.11.0</sup>: `cluster="true"` on a point layer merges the points that would overlap into count bubbles that split apart as the reader zooms in — same layer, same data, same styling for the points that stand alone. `cluster-properties` carries sums, means or the commonest category onto each bubble, bubble sizes stay meaningful at every zoom, and a click flies to where a bubble splits. See [Clustering](/onlymap/authoring#clustering-overlapping-points).
- **Print-ready cartographs** <sup>new in 0.8.0</sup>: the separate `@nika-js/onlymap/cartograph` entry composes millimetre-based map sheets with live or static georeferenced frames, derived legends, graticules, scale bars, north arrows, press marks, and atlas export. It stays out of the interactive-map bundle, and a static-only sheet never loads the map runtime. A frame can name **fallback sources** <sup>0.10.6</sup> — a capture it shows when its live map cannot load where the sheet is opened — and an atlas can be **paged by its reader** <sup>0.10.9</sup> with the keyboard or an on-sheet control. See [Cartographs & Atlases](/onlymap/cartographs).
- **Maps in a real projection** <sup>new in 0.10.0</sup>: `crs="EPSG:5070"` on `<om-map>` draws the whole map in that projection's plane — parallels curve, an equal-area map is genuinely equal-area, a national-grid sheet is drawn in its own grid. Albers, the UTM zones, British National Grid, Swiss LV95, Lambert 93, RD New and more are built in; anything else takes a `+proj=` string. The authored camera stays geographic. See [Cartographic Maps](/onlymap/authoring#cartographic-maps). Since 0.12.0 a projected map can show satellite or OpenStreetMap imagery too: an image `TileLayer` is warped into the projection.
- **Data in any coordinate system** <sup>new in 0.12.0</sup>: files in a national grid, State Plane or UTM zone — eastings and northings in metres — land in the right place instead of in the ocean. A shapefile's `.prj`, a FlatGeobuf or GeoParquet header, or a GeoJSON `crs` member is read automatically; a CSV declares it on the layer with `crs="EPSG:27700"`. Common grids and every UTM zone are built in, and any other EPSG code is looked up once at epsg.io. See [Data in a local grid](/onlymap/authoring#data-in-a-local-grid).
- **A globe** <sup>new in 0.12.0 · preview</sup>: `projection="globe"` on a map with a basemap draws the Earth as a sphere you can spin, and zooming in turns it into the ordinary flat map. Layers and the camera are written exactly as before, and it switches live. See [A globe](/onlymap/authoring#a-globe).
- **Shaded relief as a layer** <sup>new in 0.9.1</sup>: `<om-layer type="HillshadeLayer" src="terrarium">` draws shaded terrain from keyless global elevation tiles on a flat map, or `shading="hillshade"` turns a `COGLayer`/`ZarrLayer` DEM of your own into relief that shows *through* a colormap. Up to four suns (`sun-azimuth="315 45 135"`) for Swiss-style multi-directional relief; seamless tile edges, true shape at every latitude, and it works on a projected map.
- **Geometry your data doesn't contain** <sup>new in 0.10.0</sup>: `<om-transform>` inside a layer adds `simplify`, `smooth`, `dot-density`, `buffer` (with `repeat` and `fade` for the engraved coastal vignette of old charts) and `contour` (elevation lines marched off a DEM). Sizes are millimetres on the page.
- **Labels that follow the line they name** <sup>new in 0.10.0</sup>: `<om-layer type="TextOnPathLayer">` runs a river's name along the river. It reads the right way round whichever way the line was drawn, slides to the straightest stretch it fits on <sup>0.10.5</sup>, and drops a name that does not fit rather than squeezing it.
- **Export a map as editable vector** <sup>new in 0.10.0</sup>: `snapshot({ format: "svg" })` gives real `<path>` outlines and real `<text>` labels for Illustrator or a print shop, with relief and imagery placed as images underneath.
- **A printed finish in one attribute** <sup>new in 0.9.0</sup>: `<om-effect preset="vintage">` treats the rendered frame — seven looks ship, every one built from named operations you can write yourself, sized in millimetres so a 600 dpi export has the same texture you tuned on screen. An `effects` widget <sup>0.9.1</sup> switches finishes live, and undo sees it. See [Print Finishes](/onlymap/authoring#print-finishes).

### A Full 3D Scene, Still Just Attributes <sup>new in 0.3</sup>
- **Terrain**: `terrain="terrarium"` adds real elevation with no configuration (keyless AWS tiles). Geographic layers drape onto the surface automatically. You can also give your own DEM tile URL or register presets.
- **Scene lighting**: set `lighting="daylight|studio|flat|custom"`, with `lighting-*` attributes for fine control. `lighting-sun-date` computes the sun position from a date and the map location. A `lighting` widget shows these as presets and sliders.
- **Snapshots**: `map.snapshot()` captures the basemap and the WebGL canvas together, as a PNG data URL or a Blob, or as editable SVG with `{ format: "svg" }` <sup>0.10.0</sup>. Use it for print and export pipelines.
- **Camera limits as author controls** <sup>0.8.1 / 0.8.3</sup>: `max-pitch` caps how far a map can be tilted and `min-zoom` floors how far it can be zoomed out — for a kiosk or embedded map that should stay within its intended view. Neither is applied automatically.
- **BIM / IFC models** <sup>new in 0.6.1</sup>: `<om-layer type="BIMLayer" src="./model.ifc">` (or the `ifc-loader` drop-zone widget, with multi-model federation) parses IFC in the browser via CDN-fetched web-ifc and renders it as 3D Tiles. `pick-features` gives per-element picking on any 3D Tiles layer; declarative isolate/hide/ghost, colour-by-property, an `ifc-browser` model tree, a `feature-inspector`, and an `ifc-clash` overlay come as attributes and widgets.
- **Cut, export, and pick inside a 3D scene** <sup>new in 0.6.2</sup>: three tools that work on whatever 3D content is already loaded — 3D Tiles, BIM models, extruded vector geometry alike. A **clip box** (`<om-map clip-box-min="[lng,lat,elev]" clip-box-max="…">`, or the `clip-box` widget with draggable face handles) cuts the scene open; `clip-box-invert` shows what is outside instead, `clip-box-highlight` dims the cut-away geometry instead of removing it, and `clip="off"` opts a layer out. **Region export** (`<om-widget type="draw" export-3d>`) downloads the 3D content inside a drawn footprint as a portable GLB, or `export-3d="b3dm"` for Cesium and 3D Tiles pipelines. **`pickable="3d"`** opts a layer into depth picking, so a click on a building face resolves on the face and carries a real elevation, instead of the ground point behind it.
- **Snapping to real geometry** <sup>new in 0.6.2</sup>: `<om-map snap="vertex edge midpoint" snap-tolerance="12">` refines a click or hover to the nearest vertex, edge, or edge midpoint of whichever feature is under the cursor — including a BIM model's own wall corners. Vertex wins over midpoint over edge; hold Space to place a point without snapping, the usual CAD convention. `snap="off"` opts a layer out.
- **3D city models** <sup>new in 0.5</sup>: point `data` at a CityJSON file (`.city.json`, or a streamed `.city.jsonl`) — national building datasets such as 3DBAG and PLATEAU. The library decodes it to extruded footprints by default, or to real per-face roof geometry with `?om-surfaces=1`, and reprojects national coordinate grids (NL, CH, DE, JP, AT, SG) automatically.

### Data That Stays Fresh
- **Formats**: JSON/GeoJSON, CSV/TSV, Apache Arrow and GeoArrow (columnar fast path, zstd IPC), Shapefile with `.dbf` attributes, KML, GPX, the cloud-native **FlatGeobuf** (`.fgb`) and **GeoParquet** (`.parquet`) vector formats, and **CityJSON / CityJSONSeq** (semantic 3D city models). Large parsers load on first use.
- **GeoTIFF and Cloud-Optimized GeoTIFF** <sup>new in 0.3.1</sup>: `<om-layer type="COGLayer" src="./dem.tif">` streams raster tiles by HTTP Range request. The min/max restretch and the colormap are GPU uniforms, so the tiles are not fetched again. Nodata pixels are transparent.
- **Zarr / GeoZarr rasters** <sup>new in 0.5.11</sup>: `<om-layer type="ZarrLayer" src="./x.zarr" variable="temp" select="time=0">` renders chunked N-dimensional array data (climate/weather grids, datacubes) on the GPU. Pin the non-spatial dimensions with `select`; GeoZarr stores georeference themselves, a plain Zarr takes manual `bounds`/`crs`/`spatial-dims`. `src` can point at any CORS-enabled public remote store — no server setup needed.
- **Georeferenced drone photos** <sup>new in 0.5.7</sup>: `<om-layer type="ImageOverlay" src="./DJI_0123.jpg" georeference="exif">` reads a JPEG's EXIF/DJI-XMP, computes its WGS84 footprint, and overlays the image — no manual corner-pinning. `OmMap.resolveImageOverlay(file)` preprocesses once for saved maps; explicit `bounds` reconstructs without re-reading EXIF.
- **Live sources**: WebSocket streams with upsert-by-key and burst coalescing. Polled REST snapshots with `refresh="5s"`.
- **Routing and tracking** <sup>new in 0.6.7–0.6.11</sup>: `<om-layer type="Route">` draws a styled route (casing, line, origin/destination markers) from a GeoJSON LineString you already have, or resolves one from `origin`/`destination` through a pluggable `RoutingProvider` — a ~15-line adapter covers OSRM's keyless demo server, Mapbox, OpenRouteService, or your own engine. `follow="fit-route"` frames the camera on arrival, and `om-route-resolved` hands the page the resolved geometry, distance, duration, and legs. `<om-layer type="Tracking">` renders a moving entity that glides between GPS fixes with bearing-based rotation, an `arrow`/`car`/`motorcycle` marker tinted per entity, and an optional follow camera; the position feed is ordinary layer `data` (a WebSocket stream, a polled endpoint), not a separate API. Link the two with `progress-from` and the route splits live at the marker: `tail="none"` hides the traveled portion (the client view), `tail="dim"` darkens it (the operator view).
- **Multi-dimension GPU filters** <sup>new in 0.6.5–0.6.6</sup>: up to 4 numeric ranges (`filter-fields`) and up to 4 categorical keep-lists (`filter-category-fields`) filter a layer at once, combined on the GPU with no data re-upload. The same `filter` widget renders a slider for a numeric field and a checkbox list for a categorical one, and widget statistics respect every active dimension.
- **Private endpoints**: `OmMap.configureData({ headers, credentials, fetch })` keeps credentials out of the markup.

### Application UI Without an App Framework
- **Widgets**: legend, layer switcher, basemap switcher, lighting controls, zoom controls, undo/redo, scale bar, attribution, GPU filter sliders (including readable date labels for epoch-millisecond fields), a play/pause `time-slider` for temporal data, live Vega-Lite charts, a drawing toolbar, a measure tool, a clip-box control, and an event-driven `dynamic-chart`. You can also write custom widgets with a typed context (`ctx.data`, `ctx.stats`, `ctx.viewport`, `ctx.emit`).
- **Measurement, including cut/fill volume** <sup>new in 0.6.2</sup>: `<om-widget type="measure" modes="distance area volume">` measures geodesic distance and area, and — in `volume` mode — real earthworks cut and fill. Outline a footprint and the library integrates the terrain DEM cell by cell against a base surface, so one shape can report cut *and* fill on sloping ground, each with a published ± error quoted against the DEM's own ground-sample distance. Choose the base surface with `base-surface` (`custom` drag-a-plane, `triangulated` boundary TIN, `plane`, `lowest`, `highest`, `average`). `density`, `swell`, and `shrink` add Bank/Loose/Compacted volumes and tonnage; `profile` samples an elevation profile around the footprint for a `dynamic-chart` to plot. Volume mode needs `terrain` on the map.
- **Safe date formatting**: `formatDate($time, 'datetime', 'UTC')` turns epoch-millisecond or ISO fields into readable `get-text` labels without enabling arbitrary JavaScript. The same date style and time-zone contract is available on the built-in filter widget.
- **Managed, adaptive layout** <sup>new in 0.4</sup>: `position` puts a widget in one of 8 logical slots (`top-start` … `bottom-end`), and the library sets the pixel position. Widgets in the same slot stack with a shared gap, and small controls next to each other join into one group. The map attribution and the license badge sit in the bottom slots as normal members, so they do not cover a widget. On narrow maps (640px or less by default; change it with `--om-widget-fold-breakpoint`) the widgets fold into drawers, and a slot dims when an open popup covers it. `<om-map widgets-hidden>` hides all your widgets but keeps them in the page, and `position="manual"` turns off management for one widget.
- **Classified symbology** <sup>new in 0.6.12</sup>: `classify-by="magnitude"` computes choropleth-style class breaks from the data itself — `classify-scale="quantile|equal-interval|jenks"`, 2–12 classes, and 14 named color ramps (`viridis`, `turbo`, `ylorrd`, `spectral`, …) — and the legend shows the computed classes automatically. No hand-written domains or color lists.
- **Temporal playback** <sup>new in 0.6.12</sup>: `<om-widget type="time-slider" layer="quakes" field="time" duration="20s" loop>` plays a time field back through the ordinary GPU filter — cumulative reveal or a sliding `window` — so statistics, undo, and stories stay coherent with the animation.
- **Symbology-aware legends** <sup>new in 0.3</sup>: the legend uses each layer's real color styling. A continuous `scale()` ramp becomes a gradient bar with domain labels. A threshold scale becomes discrete class ranges. A categorical expression becomes a swatch palette. A raster colormap becomes its ramp. You do not configure the legend.
- **Themeable from plain CSS**: each built-in widget reads `--om-widget-*` custom properties (`om-map { --om-widget-bg: #111827; --om-widget-fg: #f9fafb; }`). You can set a dark theme with one CSS rule and no JavaScript.
- **Overlays and behaviors**: HTML popups anchor to map coordinates or to a picked feature. Declarative `on="click|hover|drag|load"` interactions need no event-handler code.
- **Map stories**: an `<om-story>` has steps that fire the same actions as behaviors, including basemap, lighting, and terrain changes. A player widget plays the steps, and you can scrub to any step.
- **Travel-map animations + external renderer support** <sup>new in 0.6.18</sup>: trace steps take `follow` (camera rides the drawing tip) and `easing`; `anchor="surface"` puts labels on the shapes themselves; and `whenSettled()` + interpolating `seek()` + the `data-om-recording` determinism switch let Remotion-class frameworks render stories frame-by-frame with byte-identical output.
- **Sharp 3D flybys + video export** <sup>new in 0.6.17</sup>: `<om-story warm-tiles>` pre-loads a route's 3D tiles before playback; `<om-story paced>` holds each frame until tiles are sharp (no blurry frame, ever); and `npx onlymapjs record map.html --out flyby.mp4` turns a story into a video with every frame fully refined — `--gpu` for several-times-faster takes on heavy scenes.

### Built for Verification
- **`OmMap.validate(html)`** returns structured errors, and each error has a fix. Add the `validate` attribute for a live error panel on the page.
- **Headless test harness**: `mountForTest` runs full behavioral tests (picks, widgets, overlays, real projection math) in jsdom or happy-dom, with no WebGL.
- **Layout audit** <sup>new in 0.4</sup>: `npx @nika-js/onlymap check-layout <manifest.html>` checks the real widget layout in headless Chromium at several viewport widths. It confirms that no widgets overlap, that each widget is hit-testable and in its slot, and that same-slot edges align. It prints structured `{severity, element, message, fix}` diagnostics and exits 0 or 1. You can also import `auditLayout(page)` into your own Playwright suite.
- **React adapter**: `@nika-js/onlymap/react` gives `<OmMap>`, `<OmLayer>`, `<OmWidget>`, `<OmOverlay>`, and a typed `useOmMap()` hook over the same core. React keeps the state, and the adapter does not conflict with the virtual DOM.
- **Custom layer classes**: `@nika-js/onlymap/deck` re-exports the bundled deck.gl classes. `OmMap.registerLayer` extensions use the renderer's own class hierarchy. A desktop app can register domain layers (local-file rasters, catalog sources) as first-class manifest types.

### Framework & Programmatic Integration <sup>new in 0.4</sup>
- **`MapController`**: a programmatic front-end for frameworks. Typed `LayerDescriptor`s drive the same reconcile core, with no DOM manifest. It adds camera methods, `emit`, `injectPick`, `snapshot`, the picking queries `pickAt`/`pickRect`/`unproject` with a `pickMode` switch <sup>0.11.5</sup> (also on `<om-map>`), and `onViewChange`/`onMapPoint`/`onTilesetLoad` callbacks.
- **External-store contract**: `getStore(token)` gives a `{subscribe, getSnapshot}` store for each token (`viewport`, `selection`, `layers`, `data:<id>`). The snapshots are cached, immutable, and tagged with an `origin`. You can use them directly with React's `useSyncExternalStore`, MobX, Redux, or Zustand.
- **Consumer events**: `om-view-changed` fires when the camera settles. `om-map-point` fires on each click or hover with the map coordinate — use it for custom capture tools that the draw widget does not cover. `om-tileset-load` gives a `Tile3DLayer`'s live `Tileset3D`, for tools such as region export. `om-route-resolved` hands over a `Route` layer's resolved path — normalized geometry, distance, duration, legs, and bounds — so a page can render an ETA or a turn list without re-fetching the route. `om-measure` carries the measure widget's full readout — distance, area, cut/fill volumes with their error bounds, material-adjusted figures, and the elevation profile series — so you can render your own readout instead of the built-in panel.

## Roadmap

These features are designed but not shipped yet: Mapbox GL basemaps, depth-interleaved 3D compositing, a globe without a basemap (and text, icon and arc layers on a globe), SSE transport, `dblclick` behaviors, the typed fluent builder, and stories and draw as React components. On cartography: relief cannot yet be masked to land, `contour` samples in the DEM's Mercator grid even on a projected sheet (the lines themselves project exactly), and native-CRS tile pyramids are deferred. The README lists the current state in its "Not implemented yet" section at each release.
